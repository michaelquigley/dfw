# PDF stage 1

The product/library design lives as one spec/work-order pair in the sibling gloss repository (`../gloss/docs/future/print-to-pdf*.md`), not as a second dfw spec. System Chromium is an export-only dependency; the main Linux window deliberately stays WebKitGTK. Terminus review 'f4ab1351d46f' returned one blocking finding, 'pdf-unsupported-opt-in': it wanted an unsupported PDF adapter to prevent the window from opening. Michael vetoed that finding and directed the canon adjustment. PDF remains an optional action with queryable support and an explicit error on use, unlike close protection that must hold when the window opens. No implementation change was made for the veto. The visible native chooser acceptance is still pending; do not infer it from the passing headless output tests.

Two details emerged only when the proof became a restricted renderer. Chromium's automatic `/favicon.ico` request violates an exact resource manifest unless the printable HTML supplies an empty data-URL favicon; gloss's stage 2 document wrapper must do that too. On the tested Snap Chromium 153, `--disable-extensions` alone still allowed component background pages. The additional component-background-extension flag is needed; the remaining `browser_ui` target is Chromium infrastructure, not an authored page, popup, frame, or worker.

The existing df version binds structs, not top-level maps. CDP envelopes therefore use a `dd` extra-field wrapper around explicit foreign-key maps; its key-preservation tests are load-bearing. This avoids both a dependency upgrade unrelated to export and snake-casing CDP's camelCase fields.

The operation context is also cancelled when the chooser releases its slot. Queue the native result before that cancellation, and let the caller wait until release completes before returning it; otherwise a successful choice can race its own cleanup into a cancelled result, or the immediately following render can see a still-busy capability.
