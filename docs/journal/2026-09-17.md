# 2026-09-17

## close veto, stage 1

- `desktopWebView.Run` always dispatches a readiness bootstrap before entering the native loop, even with a nil `OnCloseRequest`. This is deliberate: the termination coordinator replaced the lossy atomic window pointer in `Run`, and readiness must be declared from the UI thread so a supervisor failure racing with startup is consumed there instead of dropped. Do not gate it on the callback.
- `terminationCoordinator.request` calls `dispatch` while holding its mutex. That is what closes the ready-to-ended race; it also means the dispatch operation must be asynchronous (the pinned binding's `Dispatch` is, on both GTK and Win32). A synchronous fake in a test would deadlock, which is why `termination_test.go` captures functions instead of running them.
- `closeController.close` calls its terminate function outside the mutex. The terminate function is the coordinator's `request`, which takes its own lock; keep that ordering so a re-entrant path cannot deadlock.
- The Linux README sequence was driven on this machine with `GDK_BACKEND=x11` and a scratch X11 program sending `WM_DELETE_WINDOW`, because the session is Wayland and GNOME Shell's `Eval` is disabled. All five steps held (pending/1, dropped repeats, keep-open to idle, pending/2, close exits 0 with window state saved). A native Wayland title-bar click has not been exercised by an agent; the GTK `delete-event` path is the same, but treat the Wayland click as Michael's check.
- The terminus canon has no `projects/dfw/rubric.yaml`, so stage reviews ran ad-hoc against the golang and general conventions with blocking on. `camelcase-file-naming` was left out: the package already uses snake_case with platform suffixes, and the work order names the new files that way.
- Stage 2 (Windows adapter, docs, README, closeout) is not started. `close_request_unsupported.go` is `!linux` until then, so a configured callback fails on Windows by design at this stage.
- Terminus rounds on stage 1: four ad-hoc rounds, the fourth `clean`. Round 1 flagged `newConfiguredWebView` under constructor-convention; the function predates this arc, but it was renamed to `newConfiguredDesktopWebView` (two callers plus the work order) rather than carried as an open finding. That rename is the one disposition Michael may want to veto; the other findings were comment casing and a quoted platform value.
- A dfw canon now exists uncommitted in the terminus-canon working tree (`projects/dfw/`): a rubric plus six project-local qualities harvested from `docs/current`, `doc.go`, the README non-goals, and the close-veto seam census. `camelcase-file-naming` and `changelog-format` were deliberately not adopted: the package uses snake_case with platform suffixes and the repo has no changelog. The first rubric review over stage 1 flagged the missing Windows adapter as a controller-triple violation; the quality gained a staged-landing boundary rather than the code changing, and the close example README now says Windows arrives in the next stage.
