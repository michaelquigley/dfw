# Tray quit hook and live control

The handle is a value the application makes with `tray.NewControl()` and passes in `DaemonApp.Control`, not a start callback. `Daemon` blocks, so it can't return one. A callback would also leave a gap: `Daemon` starts serving HTTP before systray is ready, so a handler could change state before the callback hands over a handle, and that change would be lost. Mega's live icon is exactly the kind of state that changes early. A value the product owns from the start can be wired into its server before `Daemon` runs. It records calls until the tray is bound, then applies the latest value of each. A `Stop` before `Daemon` is latched and quits once the tray is up. A Control serves one `Daemon` call; reuse returns `errControlReused` before `Listen` runs.

`Control.end()` must run before `systray.Quit()`. On Linux, systray's `SetIcon` calls `props.SetMust`, which panics if the D-Bus connection has closed. On Windows, `quit()` deletes the notify icon on the calling goroutine before `onExit` runs. `runTray`'s `quit` wrapper ends the control first on every route (Quit, Stop, server failure, configure error), and `onExit` ends it again in case some route bypasses the wrapper. Control holds its mutex across the systray call. That serializes systray's unsynchronized `MenuItem` field writes and makes `end` wait for any call in flight. Don't move the backend calls outside the lock.

`OnQuit` is the synchronous `func() bool` the card specified, not a `CloseRequest`-style async request. Long decisions finish with `Control.Stop`. systray's `ClickedCh` is unbuffered and drops clicks that arrive with no receiver, so a Quit chosen while `OnQuit` runs is dropped. There is no drain loop because none is needed.

Considered and left out: item tooltips, adding or removing items at runtime, and access to Open Window or Quit through the handle. None were asked for, and adding or removing items would change the index-based `Item(i)` contract.

The demonstration lives in its own tray-only fixture, `examples/dfw-example-tray`, and not in `dfw-example-watch`. Terminus raised `examples-stay-fixtures` against putting it in the watch example (review `1a305c902fdf`, F1), and Michael chose a separate example. The watch example's menu stays fixed.

Verified on a live GNOME/Wayland session (Ubuntu) by running the fixture README's sequence, sending dbusmenu `clicked` events with `gdbus` rather than clicking by hand: the busy icon, tooltip and labels; Quit declined twice while busy and allowed when idle; and `POST /api/stop` while busy, and the countdown item, both ending the daemon. Every run exited 0 and removed `daemon.json`. Not verified: Windows, and how GNOME's AppIndicator extension renders the tooltip. In the SNI ToolTip tuple, the text is the title field.
